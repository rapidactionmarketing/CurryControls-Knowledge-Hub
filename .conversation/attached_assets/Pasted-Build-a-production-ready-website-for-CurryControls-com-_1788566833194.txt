Build a production-ready website for **CurryControls.com**.

The site should be a modern, independent technical knowledge hub focused primarily on control systems, automation, instrumentation, SCADA, PLCs, industrial networking, control panels, and the water/wastewater industry.

It should also provide a professional platform for highlighting independent software and technology projects relevant to engineering, controls, construction, estimating, documentation, cybersecurity, communications, and technical workflows.

The website must NOT present itself as the continuation, successor, affiliate, or current operating business of the former Curry Controls Company.

# 3. REQUIRED ENTRY NOTICE

Before a visitor can view the main site, display a modal notice over the page.

Dark navy translucent background overlay.

White modal card.

Heading:

ABOUT CURRYCONTROLS.COM

Text:

"CurryControls.com is currently owned and maintained by Eric Sullivan.

Eric Sullivan is not affiliated with Curry Controls Company. Eric previously worked with Curry Controls Company and left the company in 2021. He is currently employed by General Control Systems, Inc.

General Control Systems, Inc. is a separate company and is not affiliated with Curry Controls Company."

Button:

ACCEPT & CONTINUE

The visitor must click the button before accessing the main site.

Use sessionStorage so the notice appears once per browser session.

Do NOT call this an agreement.

Do NOT use phrases such as:

* Terms and Conditions
* Legal Agreement
* I Agree
* Waiver
* Release

It is an informational acknowledgment only.

Implementation concept:

if (!sessionStorage.getItem("curryNoticeAccepted")) {
showNotice();
}

function acceptNotice() {
sessionStorage.setItem("curryNoticeAccepted", "true");
hideNotice();
}

Make the notice content editable from a centralized configuration file.

# 33. IMPORTANT PRODUCT-POSITIONING PRINCIPLE

CurryControls.com should not look like an advertising microsite for the software projects.

The hierarchy should always be:

1. Useful technical controls information
2. Practical engineering knowledge
3. Water/wastewater controls expertise
4. Troubleshooting/reference library
5. Relevant tools and software projects

The projects should feel like useful tools emerging from the same technical ecosystem, not advertisements inserted into unrelated content.

The long-term goal is for someone searching for practical control-system information to discover CurryControls.com because the technical content is genuinely useful, then naturally discover SuitePlans, SuiteBids, KeyDocs, SecurelyFax, and other relevant tools.

Design and build accordingly.
